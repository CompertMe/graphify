graphify for Laravel

The original graphify read PHP as plain classes, so a Laravel app came out as islands. Every Laravel convention was invisible to it: routes, views, Inertia pages, Eloquent, jobs, gates and config keys. The laravel branch models those conventions. One query can now follow a request from the route to the page that renders it, and back from the page to the routes it calls.

Use it on your project

Install the Laravel build once per machine, then build the graph from the folder that contains artisan. Install this build before you use /graphify in any assistant, because the skill otherwise installs the official package, which has no Laravel layer. The LARAVEL.md guide has the one-line setup for Claude Code, Cursor, Codex and other agents, plus a prompt you can paste into any assistant.

uv tool install --force "git+https://github.com/CompertMe/graphify@laravel"
cd your-laravel-app
graphify install --project      # Claude Code · Cursor: graphify cursor install
graphify update .
graphify explain "GET /dashboard"

How it was built

  • Phase 0, PHP core: class-name resolution, typed method calls, enum cases, two wrong-binding bugs.
  • Phase 1, routing: route nodes with URI, name, middleware, groups, resources and module route files.
  • Phase 2, views and front end: Blade, components, Livewire, Inertia pages, route() in Vue and Blade.
  • Phase 3: data layer, runtime wiring, authorization, config and translation keys.
  • Phase 4, hardening: incremental-build correctness, ~30–45% faster passes, sync with upstream 0.9.93.

Laravel logic lives in its own package, graphify/extractors/laravel/, and only switches on for Laravel projects. A non-Laravel project produces byte-identical output.

Limits and honesty notes

  • App A resolves its theme views through a small .graphifyrc mapping, because the theme is chosen at run time. Those edges are marked INFERRED.
  • Six @includes in app A depend on a runtime path and stay unresolved. A second dispatch of the same job in one method shares a single edge.
  • Some measures were tightened along the way to skip code inside comments, which is why a few site counts differ slightly from the first audit.
  • Convention-based links (table names, policy discovery, listener discovery) are marked INFERRED. Facts read directly from the source are EXTRACTED.

Upstream

The generic PHP and JS fixes are offered back to the original project as seven small pull requests, each with a regression test that fails before the fix. Whether the Laravel layer itself goes upstream is open as a proposal.
